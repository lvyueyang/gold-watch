本技术文档面向开发与运维，描述项目的技术选型、运行环境、数据模型、API 规范、认证方案、部署流程、可观测与排障。设计理念与产品说明详见 [设计方案](./设计方案.md)。

## 1. 技术栈与运行环境

- 前端/服务端框架：Next.js 16（App Router）
- 部署形态：OpenNext for Cloudflare（将 Next 构建为 Workers 形态运行）
  - 入口与构建脚本参考 [package.json](file:///Users/lyy/code/project/gold-watch/package.json#L33-L42)
  - Wrangler 配置参考 [wrangler.jsonc](file:///Users/lyy/code/project/gold-watch/wrangler.jsonc)
- 运行平台：Cloudflare Workers（Node.js 兼容运行时已开启）
- 数据与队列（方案 A）：
  - D1：关系数据（规则/日志）
  - KV：最新价与幂等去重键
  - Queues：告警投递任务
- 样式与构建：Tailwind v4（已集成）、TypeScript
- 基础组件库：shadcn/ui（基于 Radix UI + Tailwind），图标：Lucide

注意：关于 Workers 平台配额与限制，请以官方文档为准：/workers/platform/limits（不在文档中硬编码任何数值）。

## 5. 数据模型（D1）

表结构建议如下（关键字段）：

```sql
-- instruments
CREATE TABLE IF NOT EXISTS instruments (
  id TEXT PRIMARY KEY,
  symbol TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL,
  exchange TEXT,
  precision INTEGER NOT NULL DEFAULT 2,
  status TEXT NOT NULL DEFAULT 'active',
  createdAt INTEGER NOT NULL,
  updatedAt INTEGER NOT NULL
);

-- rules
CREATE TABLE IF NOT EXISTS rules (
  id TEXT PRIMARY KEY,
  instrumentId TEXT NOT NULL,
  name TEXT NOT NULL,
  type TEXT NOT NULL,
  params TEXT NOT NULL, -- JSON string
  notify TEXT NOT NULL, -- JSON string
  active INTEGER NOT NULL DEFAULT 1,
  schedule TEXT,        -- JSON string
  createdAt INTEGER NOT NULL,
  updatedAt INTEGER NOT NULL,
  FOREIGN KEY (instrumentId) REFERENCES instruments(id)
);

-- rule_states
CREATE TABLE IF NOT EXISTS rule_states (
  ruleId TEXT PRIMARY KEY,
  instrumentId TEXT NOT NULL,
  lastValue REAL,
  inWindow INTEGER DEFAULT 0,
  lastFiredAt INTEGER,
  cooldownUntil INTEGER,
  refPrice REAL,
  state TEXT,           -- JSON string
  resetAt INTEGER,
  resetBy TEXT,
  FOREIGN KEY (ruleId) REFERENCES rules(id)
);

-- alerts
CREATE TABLE IF NOT EXISTS alerts (
  id TEXT PRIMARY KEY,
  ruleId TEXT NOT NULL,
  instrumentId TEXT NOT NULL,
  price REAL NOT NULL,
  ts INTEGER NOT NULL,
  payload TEXT NOT NULL, -- JSON string
  status TEXT NOT NULL,  -- new, delivering, done, failed, ignored
  createdAt INTEGER NOT NULL,
  FOREIGN KEY (ruleId) REFERENCES rules(id)
);

-- deliveries
CREATE TABLE IF NOT EXISTS deliveries (
  id TEXT PRIMARY KEY,
  alertId TEXT NOT NULL,
  channel TEXT NOT NULL,     -- lark/wecom/dingtalk
  webhookUrlHash TEXT NOT NULL,
  status TEXT NOT NULL,      -- success/failed/retrying
  attempt INTEGER NOT NULL DEFAULT 1,
  lastError TEXT,
  durationMs INTEGER,
  createdAt INTEGER NOT NULL,
  updatedAt INTEGER NOT NULL,
  FOREIGN KEY (alertId) REFERENCES alerts(id)
);

-- webhooks
CREATE TABLE IF NOT EXISTS webhooks (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  channel TEXT NOT NULL,
  urlHash TEXT NOT NULL,
  secretHash TEXT,
  config TEXT,              -- JSON string
  createdAt INTEGER NOT NULL,
  updatedAt INTEGER NOT NULL
);
```

索引建议：按使用频次在 alerts(ts)、deliveries(status, createdAt)、rules(instrumentId) 等列上添加复合索引。

## 6. KV 命名与数据约定

- KV_QUOTES：按标的存储最新价快照
  - Key：`quote:{instrumentId}`
  - Value：`{ price:number, ts:number, source:string }`
- KV_DEDUP：告警幂等与冷却窗口
  - Key：`dedupe:{ruleId}:{bucket}`（bucket 可按分钟或自定义窗口）
  - Value：`{ lastFiredAt:number }`

## 7. 队列消息格式（Queues）

队列 `ALERTS_QUEUE` 消息体示例：

```json
{
  "alertId": "uuid",
  "ruleId": "uuid",
  "instrumentId": "uuid",
  "price": 1140.0,
  "ts": 1730000000000,
  "notify": {
    "channels": [
      { "channel": "lark", "webhookId": "uuid" },
```

消费者读取后，按渠道适配器并发投递，写入 deliveries。

## 9. 规则评估算法（伪代码）

```ts
function evaluate(rule, tick, now) {
  if (!rule.active) return null;
  const s = loadState(rule.id) || {};

  const inCooldown = s.cooldownUntil && now < s.cooldownUntil;
  if (inCooldown) return null;

  const ok = match(rule, tick.price, s);
  if (!ok) {
    // 边沿复位
    s.inWindow = false;
    saveState(rule.id, s);
    return null;
  }

  if (rule.params.holdMs && !s.enterAt) {
    s.enterAt = now;
    saveState(rule.id, s);
    return null;
  }
  if (rule.params.holdMs && now - s.enterAt < rule.params.holdMs) {
    return null;
  }

  // 去重与冷却
  const key = `dedupe:${rule.id}:${bucket(now, rule.notify.dedupWindowMs)}`;
  if (kvHas(key)) return null;

  s.inWindow = true;
  s.lastFiredAt = now;
  s.cooldownUntil = now + (rule.notify.throttleMs ?? DEFAULT_THROTTLE_MS);
  saveState(rule.id, s);
  kvPut(key, { lastFiredAt: now }, ttlFrom(rule.notify.dedupWindowMs));

  return makeAlert(rule, tick);
}
```

其中 `match` 根据 type（touch/cross_up/cross_down/range/pct_change）进行判定；touch 推荐使用“进入窗口边沿触发 + suppressUntilReset”策略。

## 10. Webhook 适配与签名

- 统一发送接口：

```json
{
  "channel": "lark | wecom | dingtalk",
  "webhookUrl": "string",
  "secret": "optional",
  "title": "string",
  "text": "string",
  "dedupeKey": "optional string"
}
```

- 平台差异概要：
  - 飞书：支持文本/卡片，部分需要签名
  - 企微：支持文本/Markdown/卡片
  - 钉钉：文本/Markdown/ActionCard，常见签名为 `timestamp + sign`
- 失败重试：指数退避（5s/30s/2m/10m），上限 N 次；达到上限写入失败状态

签名算法与限流以各平台官方文档为准（不在本地文档固化实现细节）。

## 11. API 规范（摘要）

- Instruments
  - GET `/api/instruments`
  - POST `/api/instruments`（创建）
- Rules
  - GET `/api/rules?instrumentId=`
  - POST `/api/rules`（创建）
  - PATCH `/api/rules/:id`（编辑）
  - POST `/api/rules/:id/test`（试发，不落状态）
  - POST `/api/rules/:id/enable` | `/disable`（启停）
  - POST `/api/rules/batch-toggle`
- Webhooks
  - POST `/api/webhooks`（创建/更新）
- Logs
  - GET `/api/alerts?instrumentId=&ruleId=`
  - GET `/api/deliveries?alertId=`

请求与响应使用 `application/json`，错误返回格式：

```json
{ "error": { "code": "RULE_NOT_FOUND", "message": "规则不存在" } }
```

## 14. 安全基线

- 凭证与签名：仅通过 Secrets 与加密存储（hash/密文）；日志脱敏
- SSRF 防护：对 Webhook 域名做允许列表，禁止内网地址
- 认证失败限速：按 IP/指纹限速，采用退避
- CORS 策略：仅允许受信任源（管理台同域）
- 输入校验：对数值/区间/URL 做严格校验与长度限制

## 16. 常见问题（FAQ）

- 为什么触发到达价只响一次？
  - 使用 `suppressUntilReset` 与冷却/去重窗口避免反复抖动；需离开窗口复位后再次满足才会触发
- 能否做到亚秒级？
  - Cron 最小分钟级；如需更低延迟，采用第三方回调至 HTTP Worker 或将高频流下沉至自建服务
- Webhook 被限流怎么办？
  - 对渠道做速率限制与指数退避；超过上限记录失败并进入死信队列，后续人工或定时重试

## 17. 前端基础组件库

- 选型与原则
  - 采用 shadcn/ui 作为基础组件集，底层基于 Radix UI primitives，具备良好的可访问性与键盘导航支持；
  - 样式统一使用 Tailwind v4 原子类与设计令牌；图标统一使用 Lucide；
  - 组件采用“可组合、可覆盖”的模式，满足后台的表单、数据、反馈与导航需求。

- 组件范围（首批引入）
  - 通用：Button、Badge、Card、Separator、Tooltip、Popover
  - 表单：Input、Textarea、Select、Checkbox、Radio、Switch、Slider、Form（集成 react-hook-form）
  - 浮层：Dialog、AlertDialog、Drawer/Sheet、DropdownMenu
  - 数据展示：Table（含排序/分页 UI）、Tabs、Accordion、Skeleton、EmptyState
  - 反馈：Toast（建议集成 sonner）、Alert、Progress、Spinner
  - 导航：Breadcrumbs、Pagination、Tabs（路由态保持）

- 使用规范
  - 受控优先：表单组件优先受控用法，配合 react-hook-form 与 zod 做 schema 校验；
  - 无障碍：保留 Radix 的 aria 与键盘行为；不要移除 focus 样式；为图标按钮补充 aria-label；
  - 暗色模式：遵循 .dark 类切换；组件色值使用主题令牌（primary/secondary/muted 等）；
  - 一致性：按钮尺寸、圆角、阴影使用统一的 class 组合；避免内联覆盖主题变量；
  - 表格：大数据量使用虚拟滚动（后续引入 TanStack Table + 虚拟列表）。

- 目录与约定（建议）
  - `src/components/ui/*`：来源于 shadcn/ui 的基础组件（按需拷贝生成），不在这里写业务逻辑；
  - `src/components/common/*`：跨页复用的组合组件（如 ConfirmDialog、DataTable、PageHeader）；
  - `src/components/forms/*`：表单片段（表单布局、字段控件组）；
  - `src/app/(admin)/*`：页面级组件。

- 主题与令牌
  - Tailwind v4 主题设计变量放在 `globals.css`，包含颜色（primary、foreground、muted 等）、圆角、间距；
  - 所有组件引用主题变量，禁止硬编码色值（除特殊品牌色）；
  - 视觉密度与尺寸采用预设：sm/md/lg 三档，密度通过 class 切换。

- 集成与安装（仅文档说明）
  - 依赖（示例）：
    - `pnpm add lucide-react clsx tailwind-merge class-variance-authority`
    - 初始化 shadcn：`npx shadcn@latest init`（选择 Tailwind v4 兼容模板）
    - 生成组件：`npx shadcn@latest add button input dialog dropdown-menu ...`
  - 注意与 Next.js（App Router）集成：
    - 对使用 `use client` 的组件明确标注；
    - SSR 安全组件（如 Dialog）按 Radix 官方建议处理挂载容器；
    - 避免在服务器组件中直接引入仅客户端组件。

- 代码规范
  - 统一导出：为 ui 组件提供 `index.ts` 汇总导出；
  - 变体管理：使用 `cva` 管理 Button 等的 size/variant；
  - 图标：统一使用 Lucide，尺寸默认 16/20/24，保持行高与对齐；
  - Toast：统一封装 `useToast`，提供标准级别（success/info/warning/error）。

- 后续扩展
  - 图表组件（单独章节规划），倾向 ECharts 或 Recharts（按 Workers/SSR 兼容性评估）；
  - 富文本/Markdown 编辑器（按需引入），注意 CSR-only 兼容。
